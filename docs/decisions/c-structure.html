决策 C

结构：正文与组件的优先级 / aside 默认收起 / 窄屏两栏

这是三个 P4 结构性问题的合并决策页。它们都改变"一眼看到什么"，所以按规则先出页、不擅改。

  • 现状
    组件卡平权：回答、概念图、原文、闪卡、自测都是同样的卡片，一次全展开
  • 实测同屏量
    1440×900 下首屏能看到约 2 个组件（回答 + 概念图）
  • 窄屏现状
    ≤620px 时左右栏变抽屉，画布仍是单列

三个方案

C1现状：组件平权，全部展开

所有组件同样大小、同样展开。代价：一屏塞不下，读者要滚很久才看到结论之外的东西。

取舍与代价

方案好处代价验收层面要动什么
C1不改首屏信息密度低、要滚很久无
C2一眼看到结论；aside 不抢注意力多一次点击；折叠状态需要持久化改 surface.ensure_minimum 之外的默认展开策略 + widgets.js 初始态；新增断言：aside 类默认收起、点击可展开、状态可恢复
C3窄屏信息更完整，不再“抽屉里藏东西”引用跳转的上下文切换；抽屉相关的既有断言要重写改 accept_ui.py 的窄屏检查 + 抽屉断言
我的建议：C2 + C3（分两次做）。C2 直接解决"首屏看不到结论"；C3 影响的是窄屏这一整条交互路径，建议在 C2 稳定后再动，否则一次改两层，出问题难定位。
怎么选：把你的选择直接回给我（例如 A2 / B2 / C1），或者在这页上写意见（例如"B2 但条纹只留命中行"）。如果想看某个变体的真实效果，我也可以先把那个变体临时实现出来给你点。
