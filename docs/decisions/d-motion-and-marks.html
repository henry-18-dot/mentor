D-4 组件入场的节奏：逐个 vs 收敛 vs 一次性

背景是现场测量。真实提问路径（离线 provider）每轮 4~6 个组件，逐个入场；离线预览页 （fixtures 18 个组件）在 1440×900 下回放，逐帧采样得到这些数字：

  • 18 同帧 widget-in 峰值（不是 18 个"同时开始"，是逐个插入后并发堆叠）
  • 40 ms 组件之间的间隔（app.js:1254-1257 的 await wait(40)）
  • 200 ms 每条入场动画时长（styles.css:829）
  • 42.2 / 68.9 ms 深色 / 浅色的最长帧；>50ms 掉帧 0 / 4 个
  • 99.7% 真实提问路径的帧落在一个垂直同步内（四组配置）

结论：这不是"卡"的问题（真实路径测不到掉帧），是观感问题—— 18 条 200 ms 动画错峰堆叠，读起来像"涓流"而不是"一次入场"。下面是三个候选，点按钮可重播。

A保持现状：逐个入场，间隔 40 ms

做法：不动。
选它会发生什么：18 个组件入场总时长约 18×40 + 200 ≈ 920 ms； 语义上它是"流式抵达"（真的在逐条产出），不是加载动画。真实提问路径每轮只有 4~6 个组件， 观感是"一条条来"，与产品主张一致。
代价：组件多的时候（预览页/未来的历史回填）尾部等待感明显。

D-5 四处单边色条标记：留、改、还是去

⚠ 这一项与决策页 B 是同一题，请只在 B 页选一次。 → 去决策页 B 选色条（那边三个方案同样是真实令牌渲染，且已把本段的四种状态都覆盖）。 本段保留为**参考与实现细节**：它把四处色条逐个列出来对照，B 页是从整体观感切， 两页对同一件事的取舍判断一致（来源都是 Anthropic pptx skill 的「绝不用单边色条」）。 回答时写 B2 即可，不必再回一个 D-5。

先例调研借来的原则是「绝不用标题下划线 / 卡片单边色条」（Anthropic 的 pptx skill）； 而 mentor 现有 4 处单边色条做"位置指示"：命中行 4px 竖标、左栏命中片段 2px 竖线、 选中模式的下划线、目录项 3px 竖线。这不是"好看不好看"，而是指示手段要不要换一套—— 换掉就得给这四种状态各找一个替代视觉，否则可读性会降。

命中行（右栏原文）

现在：4px 竖标 + 底色

替代 1：整行浅底色（去掉竖标）

替代 2：inset 内阴影（视觉上更"内嵌"，不占布局）

实测：命中竖标 rgb(127,168,212) 4px 0 0 0 inset（验收脚本会断言它）

左栏命中片段

现在：2px 竖线 + line-clamp:2

替代：左侧留白 + 加粗首行

实测：border-left 2px，行夹 2 行（验收脚本会断言它）

选中的模式 chip

现在：下划线（inset 0 -2px）

替代表达：加粗 + 底色

实测：下划线 rgb(127,168,212) 0px -2px 0px 0px inset；chip 高度 34px（点击目标 ≥32px 达标）

目录 / 分组项

现在：3px 竖线

替代：inset 内阴影

先例调研原文列出的第 4 处

选择会发生什么代价
留（推荐）不动；这四种状态都靠"位置感"识别，竖标/竖线是最省版面的一类指示 与借来的原则不一致，需要在文档里写明"为什么不照搬"
改（只改命中行与左栏）改用底色/内阴影，视觉更"柔和" 会破坏既有验收断言（accept_ui.py 的样式证据断言了这两处的 border-left 与命中竖标），必须同步改断言；可读性需重测对比度
去（全部去掉）最贴原则四种状态失去位置指示，需要另做替代视觉，工作量最大

我的倾向：留，并在 docs/prior-art.md 里补一句"为什么不照搬"。 理由是这四处都是位置指示而不是"装饰性色条"，先例针对的是后者；但这条属观感，最终由你定。
